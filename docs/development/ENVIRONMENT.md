# Environment variables

Angular has no runtime environment variables. Every URL the browser uses is **baked into the JS bundles at build time** from one of the files in `src/environments/`.

## Files

```
src/environments/
  environment.ts          single file — defaults to the full-system localhost ports
```

There is **no** `environment.development.ts` or `environment.prod.ts` in this repo. The Angular CLI's `angular.json` does not declare a `fileReplacements` block, so `environment.ts` is the only environment file in use, regardless of `--configuration`.

## Current contents

```typescript
export const environment = {
  production: false,
  graphqlUrl: 'http://localhost:8093/graphql',
  documentsApiUrl: 'http://localhost:8091/api/v1',
  aiApiUrl: 'http://localhost:8092/api/v1',
};
```

The three URLs assume the meta-compose ports defined in the Go repo's `docker-compose.full.yml`:

| Backend | Container port | Host port (full-compose) |
|---------|----------------|--------------------------|
| Go core | 8080 | **8093** |
| Express documents | 8081 | **8091** |
| Django AI | 8000 | **8092** |

## Building for a different stack

For a different host (staging, production, a teammate's machine), choose one of:

### A — edit `environment.ts` and rebuild

Simplest. Edit the three URLs, then:

```powershell
npm run build
```

Deploy the new `dist/` artifact.

### B — add a per-environment file with `fileReplacements`

If you genuinely need to maintain dev + staging + prod simultaneously:

1. Create `src/environments/environment.prod.ts` and `environment.staging.ts` with the desired URLs.
2. Edit `angular.json` to add `fileReplacements` under the `production` (and any other) configuration.
3. Run `ng build --configuration=production` (or `--configuration=staging`).

This is **not** wired today on purpose — the demo only has one deployment target.

### C — runtime config (not implemented)

Some Angular apps load a `/assets/config.json` at startup to keep the JS bundle host-agnostic. We do not do this here. If you need it, write a `ConfigService` that fetches the JSON before bootstrap and store the URLs there instead of in `environment.ts`.

## What is NOT an env variable

- Authentication. The Bearer token is generated by the user logging in; it is not configured anywhere in this repo.
- Locale. The whole app is `es-BO`. To localize, run `ng add @angular/localize` and follow the standard Angular i18n workflow.
- Feature flags. There are none.

## Reading env in code

```typescript
import { environment } from '../../environments/environment';
const url = `${environment.graphqlUrl}`;
```

Do not introduce `process.env` reads (this is the browser; there is no `process`). Do not introduce `window['__ENV']` reads either — they bypass the build-time check.
